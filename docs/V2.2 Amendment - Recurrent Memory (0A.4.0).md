# V2.2 Amendment — Recurrent Memory

**Status:** ADOPTED (V2.2). Adds a NEW model, `0A.4.0`; it does **not**
amend `0A.1.0`, `0A.2.0` or `0A.3.0`, which stay exactly as they were.
Relative to Spec v4 and the earlier amendments, it replaces the feed-forward
hidden layer with an Elman recurrent one **for `0A.4.0` only**.

**Model versions**

|---|---|---|---|
| `0A.1.0` | historical single-founder (frozen) | 6 → 8 → 4 feed-forward | `6a6576bd49e86b27` |

`0A.4.0` = `recurrentMemoryModelConfig()` / `modelConfig('0A.4.0')`,
`npm run simulate -- --model 0A.4.0`, `npm run world -- --new --model 0A.4.0`.
Its configuration is the `0A.3.0` configuration with only the version changed;
there is no new tuning parameter. Hashes are platform-dependent (known gap 13
in `PROJECT_STATUS.md`).

Memory is a capability, not a behaviour: nothing tells an organism what to
remember or when to use it. Evolution decides whether it is useful.

## 1. The controller

For each organism, at each tick in which it acts:

    h_t = tanh(W_in · x_t + W_rec · h_(t-1) + b_hidden)
    outputs = sigmoid / tanh / sigmoid / sigmoid of (W_out · h_t + b_out)

- `x_t`: the unchanged ten `0A.3.0` inputs (food, boundary, energy, nearest
  visible organism).
- `h_(t-1)`: the organism's runtime memory, `hiddenLayerSize` values (8).
- Outputs, activations and the `ActionIntent` mapping (forward, turn, eat,
  reproduce; `>=` thresholds) are unchanged.
- Per hidden unit the sum is formed as bias, then inputs in index order, then
  previous hidden units in index order. With `h_(t-1) = 0` the recurrent term
  is exactly zero.
- No gates, cells or attention (no LSTM/GRU); `evaluateRecurrentNetwork` in
  `simulation-core/src/neural/network.ts`. The feed-forward `evaluateNetwork`
  refuses recurrent genomes and the recurrent evaluator refuses feed-forward
  ones.

## 2. Genome

`NeuralGenome.recurrentHiddenWeights` — hiddenSize × hiddenSize, row-major
(row = receiving unit), **only** on `0A.4.0` genomes (the key is absent on
feed-forward genomes). Parameter blocks, in this fixed order for drawing,
mutation and storage: input→hidden (80), hidden biases (8), hidden→output
(32), output biases (4), **recurrent (64, appended)** = **188** parameters.
The historical blocks are never reordered.

- **Founders:** drawn natively from BootstrapRNG with the existing
  `initSigma`, checked for finiteness and clamped to `neuralParamBounds`;
  the bootstrap perturbation (`neuralBootstrapSigma`) covers the new block
  like every other.
- **Mutation:** unchanged configuration; the 64 weights are ordinary neural
  parameters (same rate, sigma, bounds, enable flag, visited after the 124).
- **During life the genome never changes.** No backpropagation, Hebbian or
  other plasticity, reinforcement learning, reward or weight update of any
  kind.

## 3. Runtime memory

`OrganismRuntimeState.hiddenState` — runtime state, not genome.

- Founders and newborns start at exactly all zeros. A child inherits the
  recurrent **weights**, never the parent's memory.
- Sense → Decide → Resolve: each organism decides from S_t (its sensed inputs
  and its previous memory); the new memory is buffered with its intent and
  written only after every organism has decided. It advances exactly once
  per acting tick. Newborns do not act in their birth tick, so their memory
  is still zero on their first decision.
- Memory is never a sensory input, never visible to other organisms, and
  never in observer frames.
- Death ends it; nothing about memory is carried anywhere.

## 4. Founder screen

Unchanged in concept. The ten-input V2.1 probes are evaluated each from a
**fresh zero memory**, independently (no memory is carried between probes).
With zero memory the recurrent weights contribute nothing, so the screen
neither requires nor rewards memory use; a founder that ignores memory is
valid.

## 5. Canonical state and persistence

Memory is future-affecting, so it is canonical state: for `0A.4.0` each
organism record carries `genome.neural.recurrentHiddenWeights` and
`hiddenState`, and two worlds that differ only in memory hash differently.
Feed-forward records are emitted exactly as before (no new keys), so the
three historical hashes are unchanged.

A new **snapshot format v2** stores `0A.4.0` worlds; **format v1** stays
exactly as it was for `0A.1.0`–`0A.3.0`. Each model has one format, checked
before anything else is trusted; the validator requires memory (length
`hiddenLayerSize`, finite) and recurrent weights for v2 and forbids them in
v1. Nothing is migrated: v1 snapshots (including those written by `v1.0.0`
and by the V2.1 commit, committed as fixtures) load byte-exactly as
feed-forward worlds, and a recurrent snapshot cannot be relabelled as
feed-forward or the reverse. `0A.4.0` save → load → resume is exact.

## 6. Observatory

Observer protocol stays **v1**; frames are unchanged and contain no memory,
weights, inputs or intents. No new Observatory feature; the V2.1 vision cone
works as before.

## 7. Explicitly not added

Neural or memory UI, observer protocol v2, new inputs or outputs, eating-range
input, hunger modes, goals, planning, pathfinding, target persistence rules,
flocking/follow/flee rules, attack, predation, damage, mating choice,
signalling, communication, species, lineage or parent recognition, new genes,
lifetime learning, RL, plasticity, LSTM/GRU/attention, interaction changes,
ecology tuning, founder screening for memory, spatial indexing.

## 8. Observed, not interpreted

At the canonical seed 20260910 the `0A.4.0` world has one birth and dies out
at tick 2,474 (the golden hash still fingerprints the whole run); the pinned
checkpoints at ticks 1,000 and 2,000 cover it while alive. Tests and live
checks that need recurrent births use seed 8 — the first of 1, 2, 3, … whose
`0A.4.0` world is alive at tick 10,000 — with a coverage checkpoint at tick
2,500 (`6560783d7e9c5086`, 113 births). These are single trajectories of a
new model, not evidence that memory helps or hurts.
