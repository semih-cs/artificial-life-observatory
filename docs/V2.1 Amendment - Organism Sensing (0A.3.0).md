# V2.1 Amendment — Other Organisms Enter the Sensory World

**Status:** ADOPTED (V2.1, the first biological slice of V2). Adds a new
model; it does **not** amend the frozen models. Relative to
`Artificial Life Observatory - Spec v4 (Phase 0A Hotfixed).docx` and the
multi-founder amendment, it extends the §11.58 sensory contract **for model
`0A.3.0` only**.

**Model versions**

| Version | What it is | Topology | Golden hash (seed 20260910, 10,000 ticks) |
|---|---|---|---|
| `0A.1.0` | historical single-founder model (frozen) | 6 → 8 → 4 | `6a6576bd49e86b27` |
| `0A.2.0` | frozen v1 multi-founder model | 6 → 8 → 4 | `b95a0b4ef7dd8449` |
| `0A.3.0` | V2.1: `0A.2.0` + nearest-visible-organism sensing | **10** → 8 → 4 | `e54d0c11249b7849` |

All three are runnable and all three hashes are live regression tests. They
are confirmed on linux-arm64 (the development VM, Node 22.23.2); see
*Platform note* below. `0A.3.0` is reached through
`organismSensingModelConfig()`, `modelConfig('0A.3.0')`,
`npm run simulate -- --model 0A.3.0` and `npm run world -- --new --model 0A.3.0`.
`DEFAULT_SIMULATION_CONFIG` stays `0A.2.0`.

The principle is unchanged: **capabilities and constraints, not behaviours.**
This slice adds perception only — no new action, output, interaction or
strategy.

## 1. The sensory contract of `0A.3.0`

Inputs 0–5 keep their exact `0A.2.0` meaning and order: `foodVisible`,
`foodDistance`, `foodAngle`, `boundaryDistance`, `boundaryAngle`,
`normalizedEnergy`. Four inputs are appended:

| # | Input | Value with a target | No target |
|---|---|---|---|
| 6 | `organismVisible` | `1` | `0` |
| 7 | `organismDistance` | `distance / self.visionRange`, clamped to [0, 1] | `0` |
| 8 | `organismAngle` | relative bearing (atan2 against heading, wrapped to (−π, π]) / π; positive = clockwise/right; exactly `0` at zero distance — the food convention | `0` |
| 9 | `organismRelativeSize` | `(target.size − self.size) / (sizeMax − sizeMin)`, clamped to [−1, 1]; `sizeMin`/`sizeMax` are `bootstrap.geneBounds.size` (the bounds mutation clamps to). Negative = target smaller, 0 = equal, positive = larger. Physical information only | `0` |

**Target selection.** Candidates are the *other* organisms that are alive in
the authoritative pre-decision snapshot S_t (never the sensing organism
itself). A candidate is visible when its **centre point** lies in the sensing
organism's own inherited vision geometry: Euclidean centre distance
`<= visionRange` (inclusive) and `|relative bearing| <= visionAngle / 2`
(inclusive). At exactly zero centre distance the bearing is undefined and the
angle test does not reject the candidate (the food convention). No occlusion,
no body radius, no lineage/species/relationship filtering, no separate social
vision genes. The visible candidate with the smallest distance wins; an exact
tie goes to the lower organism id — an engine tie-break only, never an input.
The scan is a plain O(N) pass per sensing organism (O(N²) per tick), with no
spatial index or cache.

**Sense → Decide → Resolve** is unchanged. Sensing reads only S_t
(`state.organisms`, which the tick never modifies), consumes no RNG, and is
independent of array order. Newborns are not in S_t, so they are not seen in
their birth tick. The network still only returns an `ActionIntent` with the
same four outputs: forward, turn, eat, reproduce.

## 2. Model-specific neural dimensions

`packages/simulation-core/src/model/simulationModel.ts` is the single registry:
`0A.1.0` → 6 inputs, `0A.2.0` → 6, `0A.3.0` → 10. Bootstrap, founder
screening, the Sense phase, network evaluation and snapshot validation all ask
it by `simulationVersion`. Unknown versions are refused. `evaluateNetwork`
checks both the input length and the genome's input→hidden block against the
model's dimension, so a genome is never evaluated under another model's layout;
`stepWorld` refuses a world whose version differs from its config's.

## 3. Founders

`0A.3.0` founders are drawn natively as 10-input controllers through the
normal deterministic BootstrapRNG procedure (fixed block order, first passing
candidate wins). They are never 6-input controllers migrated to 10. The
five-check minimal viability screen is unchanged; its seven probe fixtures get
`[0, 0, 0, 0]` appended (no organism visible), and no check involves organism
inputs, so founder selection neither requires nor rewards any response to
organisms. The larger genome consumes more bootstrap draws, so `0A.3.0` diverges
from `0A.2.0` under the same seed by design.

## 4. Mutation

Unchanged: rates, sigmas, channel flags, disabled-channel draw schedules and
block/index order. The 32 new input→hidden weights are ordinary neural
parameters (124 in total instead of 92) and mutate through the same
per-parameter rule. No renormalisation for the larger parameter count.

## 5. Persistence

Snapshot format **v1** is kept: the stored shape does not change, and the
snapshot already records its `simulationVersion`, which must agree with its
config and state. The validator reads the neural dimension from that version
(6 for `0A.1.0`/`0A.2.0`, 10 for `0A.3.0`) and refuses any other length. A
snapshot is never converted between models: a `0A.2.0` snapshot restores,
steps and saves as `0A.2.0`. Snapshots written by the frozen v1 code (tag
`v1.0.0`) are committed as fixtures and re-serialise byte-for-byte and continue
exactly as the v1 code continued them.

## 6. Observatory

Observer protocol stays **v1**; the frame shape is unchanged and carries no
sensed target, sensory vector, weights or intent. The only new Observatory
feature is the **selected organism's vision cone**, drawn from the frame's
position, heading, `visionRange` and `visionAngle`. It is geometry — the field
of vision — and says nothing about what the organism sensed. The frontend
contains no sensing algorithm and remains structurally read-only.

## 7. Explicitly not added

Attack, predation, damage, energy stealing, mating choice or mate search,
signalling, communication, cooperation mechanics, friend/enemy labels, species,
lineage or parent/child awareness as inputs, organism ids as inputs, memory,
recurrent state, plasticity, reinforcement or lifetime learning, new
morphology or social-vision genes, new actions or outputs, collision redesign,
body-radius visibility, occlusion, spatial indexing, neural or sensed-target
UI, an observer protocol bump, ecological tuning.

## 8. Platform note (pre-existing, not introduced here)

The canonical hashes of all three models are reproduced on linux-arm64 (the
development VM, Node 22.23.2). On an x86_64 Linux container (Node 22.22.2) the **frozen v1 code at tag `v1.0.0`**
already produces a different `0A.2.0` hash (`ea689a61d2fd4b38`), and `0A.3.0`
gives `472d6bc8c8b9dacd` there; every same-platform equivalence test
(continuous == resumed, observed == unobserved) still holds on x86_64. The
likely cause is platform-dependent last-bit results of the engine's
transcendental functions (`Math.tanh`, `exp`, `atan2`, `sin`, `cos`, `log`).
Determinism therefore holds per platform; cross-platform bit-identity is not
currently guaranteed. See `PROJECT_STATUS.md`, *Known gaps*.
